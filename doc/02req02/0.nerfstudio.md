# 1. 一个  nerfstudio 的全流程 步骤

如何将 Nerfstudio 在 8GB 显存 (3060 Ti) 的限制下跑通。

以下是保姆级全流程：
## 第一步：准备环境 (已安装可跳过)
建议使用 Conda 创建独立环境，防止库冲突。
```sh
# 创建并激活环境
conda create --name nerfstudio -y python=3.10
conda activate nerfstudio


# 安装 ffmpeg (用于视频处理)
conda install -c conda-forge ffmpeg=6.1
# 确认版本号输出正常
ffmpeg -version 

# 执行以下命令安装 3.9.1 版本（这是目前 conda-forge 提供的最接近 3.9 的稳定版）：
conda install -c conda-forge colmap=3.9.1
# 安装完成后，检查版本号确认是否成功：
colmap --version


# 安装 PyTorch (根据你的 CUDA 版本，3060Ti 建议 CUDA 11.8 或 12.1)
pip install torch torchvision torchaudio
# 安装 nerfstudio
pip install nerfstudio
```
------------------------------
## 第二步：视频抽帧与数据准备
Nerfstudio 自带处理工具，能帮你自动调用 COLMAP。

   1. 新建文件夹：mkdir my_road_scene && cd my_road_scene
   2. 把视频放进去：例如 video.mp4。

ns-process-data video --data v.mp4  --output-dir ./data_processed --num-frames-target 200

## 第三步：开始训练 (核心：Splatfacto 模型)
在 Nerfstudio 中，针对 3DGS 优化的模型叫 splatfacto。
```sh
# export MAX_JOBS=1 用于限制编译器（如 gcc、nvcc）或构建工具（如 ninja、make）在编译过程中同时运行的并行任务数量为 1。
# 在安装 Nerfstudio、tiny-cuda-nn 或 PyTorch 扩展时，这个命令非常关键:
# 1. 防止内存溢出 (OOM):编译 C++/CUDA 代码（尤其是模板密集的库）非常消耗内存。
#      默认情况下构建工具会尝试同时开启 10+ 个编译进程。
#      这会导致内存迅速被占满，触发系统 僵死 或报出 c++: fatal error: Killed (program cc1plus) 错误。
# 2. 控制显存与 CPU 负载：限制任务数可以避免竞争显存导致的驱动崩溃。
export MAX_JOBS=1
# 
ns-train splatfacto --data ./data_processed --vis viewer --viewer.make-share-url True --logging.local-writer.max-log-size 10 


# ns-train splatfacto \
#   --data ./data_processed \
#   --vis viewer \
#   --viewer.make-share-url True \
#   --logging.local-writer.max-log-size 10  # 每10步输出一次训练日志
```

* 针对 8GB 显存的生存参数（如果报错 OOM 请加上）：

--pipeline.model.num_downsamp_steps 2 --pipeline.model.cull_alpha_thresh 0.01

* 查看效果：命令运行后会给出一个 localhost:7007 的链接，直接在浏览器打开就能看到实时渲染的场景。

------------------------------
## 第四步：导出点云 (为你后续的“识别”做准备)
训练完成后（通常 15-20 分钟），你需要把 3DGS 的高斯点导出为真正的 .PLY 点云文件。
```sh
# ns-export gaussian-splat --load-config outputs/data_processed/splatfacto/TIMESTAMP/config.yml --output-dir exports/
ns-export gaussian-splat --load-config outputs/data_processed/splatfacto/2026-03-22_230115/config.yml --output-dir exports/
```            

* 注意：导出的 .ply 文件包含每个点的 XYZ 坐标和颜色。

## 第五步：点云识别与模型还原 (你的核心业务)
拿到 .ply 后，你可以按照之前的设想开始工作：

   1. 清理点云：在 CloudCompare 中打开 .ply，删掉天空中乱飞的杂点。
   2. 获取坐标：
   * 手动：在 CloudCompare 中使用“Point Picking”工具，点击路灯根部，记录坐标。
      * 自动：使用 Python 库 open3d 加载 ply，通过离群点去除、欧式聚类（Euclidean Clustering）分割出路灯。
   3. 导入引擎：
   * 在 Unreal Engine 5 中，导入你的路灯 FBX 模型。
      * 根据记录的坐标（注意坐标系转换，COLMAP 通常是 Y 轴向上，UE5 是 Z 轴向上），将模型摆放到位。
   
------------------------------
## 针对你 3060 Ti 的终极建议：

* 分段大法：如果沿路视频很长（比如超过 100 米），3060 Ti 一定会崩。请把视频剪成 15 秒一段，分别跑出点云，最后在 UE5 里拼起来。
* 显存监控：训练时关闭浏览器多余标签页和所有视频播放器，把那 8GB 显存全留给 Python。
